# Grill Me（DSH 适配版）

用访谈把用户的想法逼到共识，而不是急着给方案。核心不是"多问几个问题"，而是**沿着决策依赖，一轮只推进一个分支**。

## 什么时候用

用户明确想被拷问时：`grill me`、`拷问我`、`压力测试这个方案`、`帮我把这个设计问清楚`。
用户想要的是"被问住"，不是"被服务"。如果用户只是想要一个方案，不要用本技能。

## 核心结构：设计树

把待澄清的事建成一棵**设计树**：每个决策下面挂着依赖它的决策。

- **frontier（前沿）** 是所有"前置已经确定、现在就能回答"的决策点。树内部维护 frontier，不必展示给用户。
- 一个决策的答案会重塑树：已定的决策把 frontier 往外推，解锁依赖它的新问题。
- 一个问题的答案如果依赖同一轮里还没定的另一个问题，它属于**后面**，不属于现在。

## 节奏：一轮一个核心问题

上游原版一次抛出整个 frontier（Q1、Q2、Q3…）。本适配版按用户要求改为**一次只问一个核心问题**——一口气抛多个独立问题会让用户随手糊弄，访谈就失效了。

每轮只输出：

```
❓ **Q1** - **<问题标题>**: <问题正文，可以多段，可以给选项>

➡️ 推荐答案：<你的推荐> —— 理由：<简短理由；缺依据就明说不确定>
```

规则：

1. **问题措辞要让"同意"等于接受你的推荐答案。** 用户回一个"对"就能推进。
2. **必须给推荐答案和理由。** 没依据就写"不确定，理由是缺少 X"，不要编。
3. **一次一个。** 不要用 `Q1/Q2/Q3` 把多个独立分支塞进同一轮；编号只用于跨轮追踪同一个问题。
4. **不要重复问。** 用户已经答过的、或已有可靠证据的，直接采用。
5. **用户反问时先正常回答**，回答完再回到 frontier 上的下一个问题。

## 事实归你，决策归用户

- **能自己查的绝不问用户。** 代码、配置、文档、日志、低风险实验——先用工具查清楚。DSH 里可以用 `read`/`grep`/`glob`/`pwsh`，需要并行探索时用 `subagent` 派一个全新上下文的子代理去查。
- **查证不要阻塞整轮。** 一个还在跑的探索是"未定的前置"：只把依赖它的下游问题挂起，先问 frontier 上其余的问题。
- **决策一定交回用户。** 把每个决策摆到用户面前，然后等。

## 收尾

frontier 空了就算完成：每个分支都走过，没有东西被默默假设。

完成时：

1. 整理一份**决策清单**（已定的是什么、依据是什么、还有什么未定），写成可落盘的形态（`PLAN.md` 或等价物）——上游原版"只问不整理"是已知缺陷，访谈产物必须留下来。
2. **在用户确认达成共识之前，不要动手实施。**

## 与上游的差异

本文件是 `mattpocock/skills` 的 `grill-me` + `grilling` 两个 skill 的合并适配版：上游 `grill-me` 正文只有一句 `Call the Skill tool with "grilling".`，DSH 没有等价的二级 skill 调用惯例，因此把方法论内联进来。完整差异见同目录 `PROVENANCE.md`。
